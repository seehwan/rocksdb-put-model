🔬 Theoretical Foundation: Why This Model?

Design Principles

V5.3 is designed based on four fundamental principles derived from empirical observation of RocksDB behavior during 120-minute FillRandom experiments.

Principle 1: Device Bandwidth as Primary Constraint

Observation

RocksDB write throughput is fundamentally limited by available device write bandwidth.

Why This Matters

  • Storage devices have finite write capacity (measured in MB/s)
  • All user writes must eventually reach the storage device
  • Device bandwidth already incorporates physical degradation effects
  • This is a measured reality, not a theoretical estimate
theoretical_max = (device_write_bw * 1024²) / record_size

Justification

By using available (not theoretical) bandwidth, we automatically capture:

  • Device-level degradation (wear, fragmentation)
  • Hardware-specific limitations
  • Real-world capacity (not idealized specs)

Principle 2: Phase-Specific Utilization

Observation

RocksDB utilizes device bandwidth differently across operational phases.

Why Different Phases Matter

Initial Phase
Utilization: ~3.34%
Fresh system, minimal overhead
Middle Phase
Utilization: ~4.7%
Active compaction, balanced
Final Phase
Utilization: ~10.1%
Mature LSM, stable operation

Justification

Phase-specific utilization factors capture the complex interplay of:

  • Compaction overhead (varies by LSM depth)
  • Read/write competition (varies by workload phase)
  • System maturity (improves predictability over time)

Principle 3: Context-Aware Bonuses

Observation

System state indicators (CV, LSM depth, amplification) provide additional predictive power.

Why Context Matters

High Volatility (Initial):
  • CV = 0.538 (53.8% variation)
  • Contains high-performance spikes
  • Represents true system capacity
  • Bonus: 1.20x exploits upside
Low Volatility (Final):
  • CV = 0.041 (4.1% variation)
  • Highly predictable behavior
  • Confident higher predictions
  • Bonus: 1.15x leverages stability

Justification

Context bonuses are independent information because:

  • CV measures temporal variation (not captured in bandwidth)
  • LSM depth indicates structural maturity (not in bandwidth)
  • WA/RA indicate efficiency state (not in bandwidth)
  • These are orthogonal dimensions that refine the base prediction

Principle 4: Calibration Factors Bridge Gaps

Observation

Base utilization alone under-predicts actual performance in Initial and Final phases.

Why Calibration is Needed

Initial Phase Gap:

Base: 1.9% (too conservative)
Actual: 3.34%
Gap: 1.76x
Solution: Calibration 1.579x
Final Phase Gap:

Base: 4.6% (too conservative)
Actual: 10.1%
Gap: 2.2x
Solution: Calibration 2.065x

Justification

Calibration factors are empirically derived from:

  • Observed actual performance across 120-minute experiments
  • Statistical analysis of utilization patterns
  • Conservative adjustment (slightly below actual for safety)

📐 Mathematical Formulation

Core Prediction Formula

Smax = (device_write_bw × 1024² / record_size) × Uphase × Cphase × Bcontext
Where:
• Smax = Maximum sustainable put rate (ops/sec)
• device_write_bw = Available device write bandwidth (MB/s)
• record_size = Size of each record in bytes (1040 bytes)
• Uphase = Base utilization factor for the phase
• Cphase = Phase-specific calibration factor
• Bcontext = Product of context-aware bonus factors

Why This Formula Structure?

This multiplicative structure reflects the cascading nature of performance constraints:

  1. Bandwidth → Ops: Physical conversion from MB/s to ops/sec based on record size
    (device_write_bw × 1024²) / 1040
  2. × Uphase: Software efficiency factor reflecting phase-specific overhead
    Initial: 0.030 | Middle: 0.047 | Final: 0.095
  3. × Cphase: Empirical calibration bridging observed vs theoretical gap
    Initial: 1.579x | Middle: 1.0x | Final: 2.065x
  4. × Bcontext: Context-aware refinement based on system state
    Initial: up to 2.440x | Final: up to 2.743x
Key Insight: Each multiplier adds independent information - they don't double-count. The formula progresses from physical constraints → software efficiency → empirical correction → contextual refinement.

Key Statistical Measures

Coefficient of Variation (CV):
CV = σ / μ

Standard deviation / Mean of QPS

Model Accuracy:
Accuracy = min(P, A) / max(P, A) × 100%

P = Predicted, A = Actual

Write Amplification (WA):
WA = Total_written / User_written
Read Amplification (RA):
RA = Total_read / User_read

🎯 Phase-Specific Algorithms

Initial Phase Algorithm

Objective

Predict performance during high-volatility early stage with high potential

Algorithm Steps

  1. Calculate theoretical maximum: T_max = (device_write_bw × 1024²) / 1040
  2. Apply base utilization: base = T_max × 0.030
  3. Apply calibration: calibrated = base × 1.579
  4. Apply context bonuses: final = calibrated × B_vol × B_warm × B_pot

Context-Aware Bonuses

  • Volatility (1.20x): Applied when CV > 0.50 - exploits high-performance spikes
  • Warmup (1.15x): Applied when runtime < 15 min - fresh resources bonus
  • Potential (1.12x): Applied with positive QPS trend - untapped capacity
Total Adjustment: 2.440x | Expected Accuracy: 75.0%

Middle Phase Algorithm

Objective

Predict performance during stable, compaction-active phase

Algorithm (Simple Baseline)

base_utilization = 0.047 # 4.7% target theoretical_max = (device_write_bw × 1024²) / 1040 predicted_s_max = theoretical_max × base_utilization
No Additional Optimization | Expected Accuracy: 92.2%

Final Phase Algorithm

Objective

Predict performance during mature, highly stable phase

Algorithm Steps

  1. Calculate theoretical maximum: T_max = (device_write_bw × 1024²) / 1040
  2. Apply base utilization: base = T_max × 0.095
  3. Apply calibration: calibrated = base × 2.065
  4. Apply context bonuses: final = calibrated × B_stab × B_mat × B_eff

Context-Aware Bonuses

  • Stability (1.15x): Applied when CV < 0.05 - excellent stability confidence
  • Maturity (1.10x): Applied when LSM_depth ≥ 7 - mature structure bonus
  • Efficiency (1.05x): Applied when 3.0 ≤ (WA+RA) ≤ 4.5 - efficient steady state
Total Adjustment: 2.743x | Expected Accuracy: 86.4%
